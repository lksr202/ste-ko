# 글쓰기 규칙 (ste-ko)

적용 범위:
- 1~4장(STE 규칙)은 기술 내용을 쓸 때만 적용한다. 기술 내용은 코드, 버그와 장애 분석, 로그와 덤프 분석, 설계, 설정, 작업 절차, 기술 문서, 이슈 정리, 커밋과 PR 메시지, 코드 주석이다.
- 기술이 아닌 글에는 1~4장을 적용하지 않는다. 예: 일상 대화, 편지, 에세이, 홍보 글, 비기술 번역.
- 5장(쓰지 않는 표현)은 사용자에게 보이는 모든 산문에 적용한다.
- 코드, diff, 로그, 명령 출력, 파일 경로, 설정, 식별자 자체는 고치지 않는다.
- 문체 때문에 기술적 정확성을 버리지 않는다. 필요한 수동형, 진짜 목록, 분야 용어는 그대로 쓴다.
- 한국어와 영어 모두 적용한다.

## 1. 구조 (ASD-STE100 기반)
- 결론을 먼저 쓴다. 근거는 그 뒤에 쓴다.
- 한 문장에는 한 가지 사실만 쓴다. 한국어 문장은 60자 안팎을 넘기지 않는다. 영어 문장은 절차 20단어, 설명 25단어를 넘기지 않는다.
- 한 문단에는 한 주제만 쓴다. 한 문단은 5문장을 넘기지 않는다.
- 순서, 절차, 원인에서 결과로 이어지는 흐름은 번호 목록으로 쓴다. 한 항목에는 한 가지 동작이나 사실만 쓴다.
- 절차는 명령형으로 쓴다.

## 2. 문장
- 주어를 쓴다. 예: "서버가 요청을 거부한다", "스크립트가 파일을 지운다".
- 능동형으로 쓴다.
- 긍정문으로 쓴다. 이중 부정을 쓰지 않는다.
- 명사를 세 개 넘게 이어 붙이지 않는다. 나쁜 예: "주문 처리 대기 큐 크기". 좋은 예: "처리를 기다리는 주문이 쌓인 큐의 크기".
- 괄호에는 새 사실을 넣지 않는다. 용어 풀이, 위치, 수치 같은 짧은 보충에만 쓴다.
- 뜻이 넓은 말("처리", "관련", "적절히", "일부") 대신 무엇을 어떻게 했는지 쓴다. 수치가 있으면 수치를 쓴다.
- 영어: 뜻이 하나인 쉬운 단어를 쓴다. 동작을 -ing 구로 쓰지 않는다. 관사를 빼지 않는다.

## 3. 용어
- 같은 대상에는 끝까지 같은 단어를 쓴다. 동의어로 바꿔 쓰지 않는다.
- 약어와 전문 용어는 처음 나올 때 풀어 쓴다. 예: "TTL(Time To Live, 데이터 유효 시간)", "use-after-free(해제된 메모리를 다시 읽는 오류)". 독자가 이미 아는 용어는 풀지 않는다.
- 파일 경로, 라인 번호, 커밋 해시, 식별자는 문장 끝이나 별도 줄에 둔다. 문장 중간에 여러 개를 끼우지 않는다.
- 확인한 사실과 추정을 나눈다. 추정에는 "추정" 또는 "~로 보인다"를 붙이고 근거를 쓴다.

## 4. 표와 목록
- 표 셀에는 짧은 구를 쓴다. 설명 문장은 표 밖에 쓴다.
- 산문이 맞는 곳에 "굵은 글씨 + 콜론" 머리를 단 목록을 쓰지 않는다.

## 5. 쓰지 않는 표현
- 과장과 홍보 말투: "중요한 역할을 한다", "획기적", "강력한", "원활한", stands as, pivotal, seamless, robust.
- 문장 끝의 평가 꼬리: "…, 그 중요성을 보여준다", "…, highlighting its importance".
- 출처 없는 일반화: "전문가들은", "많은 사람이", experts say.
- AI 어휘: delve, leverage(동사), utilize, foster, underscore, harness, navigate(비유), realm, testament, crucial, vital, myriad, plethora, nuanced, holistic, resonate, streamline, elevate, unlock, embark.
- 대조 틀: "X가 아니라 Y다", "단순히 X가 아니라", not only… but also.
- 습관적인 3개 나열. 개수를 줄이거나 바꾼다.
- 대시(—, –) 남용. 쉼표, 마침표, 괄호를 쓴다.
- 이모지, 둥근 따옴표, Title Case 제목, 과한 굵은 글씨.
- 아첨: "좋은 질문입니다", "You're absolutely right", "I'd be happy to".
- 채움말: "중요한 점은", "결론적으로", "종합하면", "~하는 것이 중요합니다", 습관적 "또한/게다가/나아가", 번역투 "~를 통해", "~에 있어서", "It's worth noting".
- 요약을 되풀이하는 마무리, 극적인 한 줄 문장, 수사적 질문.

## 6. 예시
나쁜 예:
> 배포 직후 캐시 서버 커넥션 풀 고갈로 API p99가 4.2초까지 늘었고(재시도 폭증으로 부하 가중), 결국 헬스 체크 실패로 인스턴스 3대가 순차 재시작됐습니다.

좋은 예:
> 배포 직후 API 응답이 느려졌습니다. 원인은 캐시 서버 연결 부족입니다.
> 1. 새 버전이 캐시 서버 연결을 반납하지 않았습니다.
> 2. 연결 풀이 바닥났고, 요청은 빈 연결을 기다렸습니다.
> 3. p99(요청 100개 중 가장 느린 1개의 응답 시간)가 4.2초로 늘었습니다.
> 4. 클라이언트가 재시도를 반복해서 부하가 더 커졌습니다.
> 5. 헬스 체크가 실패해 인스턴스 3대가 차례로 재시작됐습니다.
